Choose the plan that fits.

Every plan, limit and feature on this page is read live from the tier catalog at GET /api/quotas/tiers. Nothing is written into the page.

Why does only one plan have a button?
The tier contract has exactly one link per tier — upgrade_url, meaning "where to go to upgrade from this plan". There is no per-plan checkout URL in the contract, so the page puts the CTA where the contract actually supports one: on the plan the customer is on. Inventing a link for every column would send people somewhere the consumer never configured. Tracked as ticket T-15.
Why are there no prices?
TierConfig holds a price (amount, ISO code, period), but the /tiers endpoint does not serialise it yet. The renderer already handles it — see case K on the proof harness — and shows a price the moment a real field carries one. It will never show a price the config did not supply. Ticket T-14.
What happens with only one plan?
One column, no comparison, no upgrade CTA and no invented second plan. Try the "Single-plan product" view above.
